PR #4517 — 4.0.x: Cherry-pick 813f6891 to fix test regressions from the PR #4505 backport

PR #4505 (GH-4504 데이터 유실 fix)가 머지 직후 4.0.x로 backport(ed31b093)됐는데, main에는 있고 4.0.x에는 없는 precursor commit 하나가 누락돼 EnableKafkaKotlinCoroutinesTests의 3개 테스트가 모두 깨졌습니다. main의 813f6891(Support CommonErrorHandler for suspend functions)을 4.0.x로 cherry-pick해 fix-forward.

GitHub PRspring-projects/spring-kafka#4517

맥락

PR #4505가 main에 머지된 직후 메인테이너(@sobychacko)가 4.0.x 브랜치로 cherry-pick(ed31b093)으로 backport. CI에서 EnableKafkaKotlinCoroutinesTests의 3개 테스트가 동시 실패:

  • test suspend function with CommonErrorHandler
  • test suspend function bounded retries with CommonErrorHandler
  • test suspend function bounded retries for two records on the same partition

메인테이너가 PR #4505 thread에 "tests are failing on the 4.0.x branch ... if need be, we can back out these changes from 4.0.x"이라고 알려옴. 로컬 재현 후 root cause 추적.

원인

backport의 새 suspend-listener 테스트 3개 모두 main에만 존재하던 commit 813f6891(Support CommonErrorHandler for suspend functions)에 의존. 4.0.x에는 이 precursor가 한 번도 backport된 적 없음.

main에서는 setCallbackForAsyncFailure(...)가 모든 RecordMessagingMessageListenerAdapter에 대해 DelegatingMessageListener extraction으로 wire됨. 4.0.x에서는 KafkaBackoffAwareMessageListenerAdapter(즉 @RetryableTopic일 때)만 wire됨. plain suspend @KafkaListener + DefaultErrorHandler 조합에서는 async failure가 failedRecords 큐로 routing 자체가 안 됨 → handleAsyncFailure 호출 안 됨 → recoverer 호출 안 됨 → latch timeout.

선택지와 결정

두 방향이 있었음:

  1. Fix forward — 813f6891을 4.0.x에 cherry-pick해 backport가 작동하게 함.
  2. Back out — 4.0.x에서 backport 자체를 되돌려 silent data loss 상태로 유지 (fix는 main에만 존재).

(1)로 결정. silent record loss는 유지되는 브랜치에 그대로 두면 안 되는 종류의 버그. 813f6891은 본질이 backport-worthy bug fix 이기도 함.

수정

813f6891을 4.0.x로 cherry-pick. 충돌은 테스트 파일 한 곳뿐 (HEAD가 backport(ed31b093)로 이미 superset of 813f6891의 테스트를 가지고 있어서) → HEAD 채택으로 자연 해소. container 코드는 auto-merge로 정확히 필요한 wiring 변경 (setCallbackForAsyncFailure(...)의 KafkaBackoffAwareMessageListenerAdapter-only 분기를 generic DelegatingMessageListener extraction으로 교체)만 들어옴.

다른 잠재적 precursor dfe52787(GH-4465 fix)은 ed31b093이 이미 container 변경(failedRecords.addLast(failedRecord) 제거)과 회귀 테스트 둘 다 통째로 흡수했기 때문에 cherry-pick 시 redundant conflict만 나서 제외.

검증

로컬 4.0.x에서 cherry-pick 적용 후 ./gradlew :spring-kafka:test 풀 스윕 통과. 깨졌던 3개 테스트 + ObservationTests(813f6891이 함께 손본 파일) 모두 green.

두 번째 commit — attribution

본 PR의 두 번째 commit은 KafkaMessageListenerContainer.java의 class-level @author 목록 끝에 Bill Kim 한 줄 추가. PR #4505가 머지될 때 누락된 contributor attribution 보강. PR body에 메인테이너 선호도 따라 drop 가능하다는 단서 명시.

DCO 해소

첫 cherry-pick commit (8fa7a8be)이 DCO bot에서 fail — 원작자 zoo-code의 Signed-off-by만 보존되고 committer(BK202503) 본인 signoff가 누락된 상태였음. git rebase -i + git commit --amend --no-edit --signoff로 BK202503 signoff 한 줄 추가하고 원작자 signoff는 그대로 보존. force-push 후 DCO status pass로 전환.
